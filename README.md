# Screen Ruler

리눅스(X11) 화면 위에 띄우는 반투명 가상 자. A4 같은 실물로 화면 픽셀 크기를 보정한 뒤, 화면에 표시된 물체(예: 모니터에 띄운 체커보드 칸)의 길이를 mm 로 잰다. 실물 자를 화면에 대다가 긁힐 걱정이 없다.

- 테두리 없는 반투명 자 막대, 항상 위에 뜸. 기울이면 창 모양도 자 모양으로 잘려서 바깥은 아래 창이 보이고 클릭도 통과한다
- 임의 각도 회전, 좌우·상하 뒤집기, 길이 조절
- A4 로 가로·세로 피치를 따로 보정하고 모니터별로 저장, 보정 결과 검증
- A 고정 · B 여러 번 고쳐 찍는 길이 측정

## 요구 사항

- Linux + X11 세션 (Wayland 에서는 창 모양 자르기와 `xrandr` 모니터 정보가 동작하지 않는다)
- Python 3.10+ 와 tkinter
- `xrandr` (모니터 위치·EDID 크기), `libX11` / `libXext` (창 모양 자르기)

외부 Python 패키지는 없다. Ubuntu 기준 시스템 패키지:

```bash
sudo apt install python3-tk x11-xserver-utils libxext6
```

## 실행

```bash
python3 screen_ruler.py                  # 마우스가 있는 모니터에 띄움
python3 screen_ruler.py --monitor DP-4   # 모니터 지정 (xrandr 출력 이름)
python3 screen_ruler.py --length 280 --angle 0   # 처음 길이(mm)·각도(°, 시계 방향)
python3 screen_ruler.py --selftest       # 계산 부분 자체 검사
```

모든 기능은 자 위 버튼으로 할 수 있고, `?` 버튼이 도움말이다.
끄기: `✕` 버튼, 또는 자를 클릭한 뒤 `Esc`. 응답이 없으면 `pkill -f screen_ruler.py`.

## 처음 한 번: 보정

화면 픽셀 1개가 실제로 몇 mm 인지(피치)를 실물로 잰다. 보정 전에는 모니터가 알려 주는 EDID 크기로 추정한다.

`보정하기 (c)` 를 한 번 누르면 네 단계를 차례로 진행한다. 가로 자로 A4 의 **긴 변·짧은 변을 한 번씩** 잰 다음, 자가 알아서 90° 로 서고 세로 자로 다시 두 번 잰다.

| 단계 | 자 | 종이 | 자에 대는 변 |
|---|---|---|---|
| ① | 가로 0° | 가로로 눕힘 | 긴 변 297 mm |
| ② | 가로 0° | **세로로 세움** | 짧은 변 210 mm |
| ③ | 세로 90° | 세운 그대로 | 긴 변 297 mm |
| ④ | 세로 90° | **다시 가로로 눕힘** | 짧은 변 210 mm |

각 단계에서 그 변을 자의 눈금 쪽 가장자리에 붙이고, 파란 선 두 개를 종이 양 끝에 맞춘 뒤 `저장 (Enter)`.

- **선 이동**: 선 근처(30 px 안)를 드래그하거나, 선을 클릭해 고른 뒤 방향키로 1 px 씩 (Shift = 10 px)
- **자 이동**: 선에서 떨어진 곳을 드래그하거나, 선을 고르지 않은 상태에서 방향키 (선에서 떨어진 곳을 클릭하면 선택 해제)
- **건너뛰기**: 필요 없는 단계. 화면에 안 들어가는 단계(예: 폭 311 mm 세로 모니터에서 가로 297)는 자동으로 건너뛴다
- **취소 (Esc)**: 아무것도 저장하지 않고 원래 상태로
- 종이가 A4 가 아니면 숫자키로 그 변의 길이(mm)를 고친다
- 보정 중에는 종이 변이 다 들어가도록 자가 잠시 길어지고, 끝나면 원래 각도·길이로 돌아온다

### 결과

축마다 **두 변 길이 합 ÷ 두 구간 픽셀 합** 으로 피치를 정한다(긴 변 비중이 더 큼). 끝나면 이렇게 표시된다.

```text
✓ 보정 완료 — 가로 0.18153 mm/px (EDID +0.01%, 두 변 차이 0.02%) · 세로 …
```

- **EDID 대비**: 모니터가 알려 준 크기와의 차이
- **두 변 차이**: 297 로 구한 값과 210 으로 구한 값의 차이. 종이 치수와 선 맞춤이 정확했는지 보여 준다
- 둘 다 보통 1 % 안쪽이다. EDID 차이가 5 %, 두 변 차이가 1 % 를 넘으면 `⚠ 다시 보정해 보세요` 가 붙는다 (대개 종이 변을 잘못 대거나 선을 잘못 맞춘 경우)
- 한 변만 잰 축은 그 값을 쓰고, 한 번도 안 잰 축은 이전 보정값을 그대로 둔다
- 보정값은 `~/.config/screen_ruler.json` 에 모니터·축별로 저장된다 (각 측정값 `samples` 와 두 변 차이 `spread_pct` 포함)

> 왜 자를 돌려야 하나: 가로 자로 재는 것은 종이를 어떻게 놓든 "가로 방향 픽셀 수"다. 가로 자로 긴 변·짧은 변을 재면 같은 가로 피치를 두 번 재서 서로 확인하는 셈이고, 세로 피치는 자를 세워야 잴 수 있다. 요즘 모니터는 픽셀이 사실상 정사각형이라 가로·세로 피치는 거의 같게 나온다.

## 검증

`검증 (t)` 을 누르면 자의 210 mm, 297 mm 위치에 초록 선이 생긴다(점선 = ±1 mm). A4 한쪽 끝을 0 눈금에 맞췄을 때 반대쪽 끝이 초록 선에 오면 보정이 맞다. 가로·세로 자 모두 긴 변(297)과 짧은 변(210)으로 확인할 수 있다. 얼마나 어긋났는지는 아래 길이 재기로 잴 수 있다. 자가 297 mm 보다 짧으면 검증하는 동안만 늘어난다.

## 길이 재기

1. 자 위를 클릭 → **A 고정**. 이후 `A → 커서` 거리가 계속 표시된다
2. 다시 클릭 → **B** (주황). 클릭할 때마다 B 만 옮겨지고, 방향키로 B 를 1 px 씩 조정할 수 있다
3. `확정 (Enter)` → 결과 고정 (빨강). 이후 클릭은 무시되고 드래그로 자를 옮길 수 있다
4. `새 측정 (m)` / 우클릭 / Delete 로 지우고 다시 시작. 확정 전 `Esc` 는 측정 취소

측정은 실물 자처럼 자를 따라가는 방향의 길이다. 눈금 쪽 가장자리가 재는 면이고, 0 은 눈금이 시작하는 끝이다.

## 조작 요약

| 동작 | 버튼 | 키·마우스 |
|---|---|---|
| 자 이동 | 드래그 | 방향키 1 px (Shift 10 px) |
| 90° 회전 | `↺90°` `↻90°` | `r` |
| 임의 각도 (0 눈금 중심) | `각도…` → 숫자 입력 → Enter | 휠 1° (Shift+휠 0.1°), `,` `.` 1°, `<` `>` 0.1° |
| 좌우 / 상하 뒤집기 | `⇋좌우` `⇅상하` | `h` / `v` |
| 길이 | `−1cm` `+1cm`, 끝 회색 손잡이 드래그 | `[` `]` |
| 투명도 | | `+` / `-` |
| 측정 확정 / 새 측정 | `확정` / `새 측정` | `Enter` / `m`, 우클릭, Delete |
| 보정 / 검증 | `보정하기` / `검증` | `c` / `t` |
| 보정 중 | `저장` `건너뛰기` `취소` | `Enter` / — / `Esc` |
| 도움말 / 끄기 | `?` / `✕` | `?` / `Esc` |

- 회전해도 자 길이는 그대로다. 자가 모니터보다 길 때만 보이는 길이를 줄이고(원래 길이는 기억), 그 상태에서 `−1cm` `+1cm` 는 보이는 길이 기준으로 조절된다
- 자가 모니터 밖으로 나가면 안쪽으로 밀어 넣는다
- 자가 거꾸로 놓이는 각도에서는 글자를 180° 돌려 늘 읽히게 한다

## 한계

- X11 전용 (Wayland 미지원)
- 모니터는 `xrandr` 출력 이름 + 해상도 + EDID 크기로 구분한다. 같은 모델을 같은 포트에 번갈아 꽂으면 보정값을 공유한다
- 비스듬한 각도에서는 가로·세로 보정값을 합성해 쓴다
- 측정은 자 방향 길이만 잰다 (화면 위 임의의 두 점 사이 거리는 아님)
